開發者指南Developer guide

開發與發布自己的來源Develop and publish your own source

這不是一般使用者的必要設定。你需要具備 Kotlin、Gradle、HTTP 與網頁解析經驗。This is not required for ordinary use. You need experience with Kotlin, Gradle, HTTP, and web parsing.

MangaFuru 目前沒有提供獨立的來源 SDK 或從 App 直接建立來源的工具。你需要自行建立相容的 Android 來源套件、輸出 APK，並透過相容 Repository index 發布。App 目前不支援直接選取 APK 安裝。MangaFuru does not currently provide a standalone source SDK or an in-app source builder. You must create a compatible Android source package, produce an APK, and publish it through a compatible repository index. Direct APK file installation is not currently supported.

01開始前需要的能力What you need before starting

  • Kotlin 與 Gradle／Android 專案建置。Kotlin and Gradle/Android project builds.
  • HTTP 請求、狀態碼、header、cookie 與登入流程。HTTP requests, status codes, headers, cookies, and login flows.
  • HTML 結構、CSS selector 與網頁解析。HTML structure, CSS selectors, and web parsing.
  • 目標服務的使用條款、存取權與合理請求頻率。The target service's terms, access rights, and responsible request rates.
不要以真實帳密或私密 token 寫入原始碼、APK、測試資料或公開 Repository。Never place real credentials or private tokens in source code, APKs, test fixtures, or a public repository.

02來源套件需要負責什麼？What must a source package do?

來源套件不是漫畫資料檔；它是可執行的連接器。一般會負責以下流程：A source package is not a manga data file; it is an executable connector. It normally owns these flows:

  1. 1目錄與搜尋。回傳熱門、最新、搜尋結果與下一頁資訊。Catalog and search. Return popular, latest, search results, and pagination state.
  2. 2作品與章節。提供標題、封面、說明、狀態、章節清單與穩定識別資料。Titles and chapters. Provide title, cover, description, status, chapter list, and stable identity data.
  3. 3閱讀頁面。依正確順序回傳每一頁，並處理必要的 request header。Reader pages. Return every page in the correct order and handle required request headers.
  4. 4可選設定。若服務需要登入、mirror 或其他選項，提供清楚且不洩漏敏感資料的設定欄位。Optional settings. If the service needs login, mirrors, or other options, expose clear settings without leaking sensitive data.

03透過 Repository 發布Publish through a repository

建置完成後會得到 APK。MangaFuru 不是直接讀取你的 Kotlin 原始碼，而是從 Repository index 找到套件資訊，再下載 APK。傳統 Repository 通常使用以下結構：A successful build produces an APK. MangaFuru does not read your Kotlin source code directly; it finds package metadata in a repository index and then downloads the APK. A traditional repository usually follows this structure:

repo/
├── index.min.json
├── apk/
│   └── example-source-v1.0.1.apk
└── icon/
    └── com.example.source.png

網站需能透過 HTTPS 公開讀取 index、APK 與 icon。檔名大小寫與 index 內容必須完全一致。The index, APK, and icon must be publicly readable over HTTPS. Filename case and index metadata must match exactly.

04最小索引資料Minimum index metadata

index.min.json 是套件索引，不是內容目錄。以下是用虛構資料表示的傳統格式：index.min.json is a package index, not a content catalog. This fictional example shows the traditional format:

[
  {
    "name": "Example Source",
    "pkg": "com.example.source",
    "apk": "example-source-v1.0.1.apk",
    "lang": "en",
    "code": 1,
    "version": "1.6.1",
    "nsfw": 0,
    "sources": [
      {
        "name": "Example Source",
        "lang": "en",
        "id": "123456789",
        "baseUrl": "https://example.com"
      }
    ]
  }
]
  • pkg 是套件的穩定安裝識別，不要在更新時隨意更換。pkg is the stable install identity; do not casually change it between updates.
  • code 必須在每次發布更新時遞增。code must increase for every published update.
  • sources[].id 必須保持穩定，否則既有書庫可能無法對回原來源。sources[].id must stay stable or existing library items may no longer map back to their source.
  • apk 必須對應 apk/ 內實際存在的檔案。apk must match a real file under apk/.

05不要只確認「可以建置」Do not stop at “it builds”

來源在 Android 工具鏈中成功產生 APK，不代表一定能在 MangaFuru 的 iOS 執行環境完整運作。發布前至少逐層驗證：Producing an APK with the Android toolchain does not guarantee complete compatibility with MangaFuru's iOS runtime. Before publishing, verify every layer:

  1. 1Repository 可載入。用完整 HTTPS index URL 加入，確認套件會顯示。The repository loads. Add the full HTTPS index URL and confirm the package appears.
  2. 2來源可安裝。確認 APK 能下載、轉換、載入，且來源出現在「探索」。The source installs. Confirm the APK downloads, converts, loads, and appears in Browse.
  3. 3完整閱讀流程可用。逐一測試熱門、最新、搜尋、作品詳情、章節與實際頁面。The full reading flow works. Test popular, latest, search, title details, chapters, and real pages.
  4. 4更新不破壞既有資料。提高版本後再次安裝，確認穩定 ID、書庫與續讀仍能對應。Updates preserve existing data. Publish a higher version and confirm stable IDs, library items, and resume mapping still work.
相容性限制：來源套件若依賴尚未支援的 Android API、較新的套件介面或特殊 bytecode，可能安裝失敗或執行時錯誤。遇到問題時，請提供可重現步驟與去敏感化的錯誤資訊。Compatibility limits: A source package can fail to install or run if it depends on unsupported Android APIs, a newer package interface, or unusual bytecode. When reporting a problem, include reproducible steps and sanitized error details.
